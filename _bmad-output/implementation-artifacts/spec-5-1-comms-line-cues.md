## Intent

**Problem:** Back-to-back story lines on the CommsPanel advance in total silence after the `comms_open` cue, so a multi-line conversation feels dead between panels.

**Approach:** Three-level radio cue set, chosen by the user on 2026-10-09: `comms_open` (unchanged) only when a channel opens; on a line advance to a **different** speaker play `comms_handover` (short squelch tail "kssh" of the last speaker releasing, then the new speaker's mic-click); on a line advance to the **same** speaker play `comms_click` (quiet mic-click only). No beep in either new cue.

## Boundaries & Constraints

**Always:** Both new WAVs are generated by `tools/gen_placeholder_sfx.py` with their own seeds, so every existing WAV regenerates byte-identical. Same voice band (300 Hz - 3 kHz) as `comms_open`, no stutter gating, no hum (stay distinct from `comms_static`). `comms_click` ≈ 40 ms, `comms_handover` ≈ 220 ms (squelch tail clearly louder than its click; renegotiated 2026-10-09, see Spec Change Log). Play with 0.0 pitch jitter, like `comms_open`. List both in `game/assets/CREDITS.md`. Record the decision in the GDD decision log as #40.

**Ask First:** Any change to `comms_open`, to combat-mode lines, or to the cut-off/silence path.

**Never:** A cue on the click that only completes a typing line; a cue on line 0 of a sequence (it already gets `comms_open`, including a queued story that starts without unpausing); any SFX for combat lines (cut-off lines and Tarek's silence beat are combat lines, so they stay untouched by construction).

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Speaker change | line N complete, line N+1 speaker differs, click | `comms_handover` plays, line N+1 shows | N/A |
| Same speaker | line N complete, line N+1 same speaker, click | `comms_click` plays | N/A |
| Complete typing | line still typing, click | line completes, no new SFX | N/A |
| Last line | last line complete, click | no line cue; next queued story plays `comms_open`, else panel closes | N/A |

## Spec Change Log

- **2026-10-09, operator listening test:** the speaker change was inaudible; the 80 ms tail decayed quickly from below the click's level, so it only smeared the click. The user agreed to rework it. Amended `comms_handover` from ≈120 ms to ≈220 ms: a 150 ms squelch tail (90 ms hold, raised-cosine fade to 0), a 25 ms gap, then the mic-click at half level; peak 0.7. Known-bad state avoided: a tail quieter than its click. KEEP: no beep, voice band, own seed, `comms_click` unchanged, the cue-selection code and tests.
