## Intent

**Problem:** In the Story 5.2 operator check, the top-left interruption box went away before the user could read it (about 2.3 s), its 0.2 s linear fade felt abrupt, its 24 px body text was small, and it made no sound at all.

**Approach:** These are the recommended options; the user didn't respond and they're easy to tune. Hold every line for `max(5.0, chars/45 + 3.0)` s. Fade out over 0.6 s with an ease-out. Raise the box body text to 26 px on a 30 px line pitch, with name 28 px unchanged, the box still 96 px tall and the top padding 6 → 4. Add radio cues: a new quiet `comms_chatter` key-in cue (squelch burst plus mic-click, no beep) when the box opens fresh. When a combat line starts while the box is still up or fading, play the 5.1 cues instead: `comms_handover` for a new speaker, `comms_click` for the same speaker.

## Boundaries & Constraints

**Always:** All numbers come from `tuning.json` and the Theme (`CommsBox` type), never hard-coded. The story panel (`CommsPanel`: name 30, text 30) and its cues are untouched. `comms_chatter` is generated by `tools/gen_placeholder_sfx.py` with its own seed. Every existing WAV regenerates byte-identical. It uses the voice band, has no beep, and peaks below `comms_open`. It plays with 0.0 pitch jitter. A 50-character line still wraps to at most 2 lines in both variants. Record the decisions in the GDD decision log (#41, amending #40's "combat lines stay SFX-free") and the UX decision log (#23). Update the docs that state the old numbers: DESIGN.md, EXPERIENCE.md, game-architecture.md and the epics Story 5.2 AC. Credit the WAV in CREDITS.md.

**Ask First:** If 26 px cannot fit a 50-character line in 2 lines, or the 30 px pitch can't be reached with the FontVariation trims. Also ask before any change to box size or position, `comms_open`, or the cut-off effects.

**Never:** A sound on fade-out or hide. Changes to the Vale accent (#E8F4FF is the UX-spec colour, and the near-white edge is intended). Changes to the story panel sizes or the hint pill.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Fresh line | box hidden, combat request | box slides in, `comms_chatter` plays | N/A |
| Back-to-back, new speaker | queued combat starts as the previous one ends (box still visible or fading) | `comms_handover` plays | N/A |
| Back-to-back, same speaker | as above, same speaker | `comms_click` plays | N/A |
| After a story | story closes, queued combat starts | `comms_chatter` (box was hidden by the story) | N/A |
| Cut-off line | Tarek cut-off requested from idle | `comms_chatter` at start, `comms_static` at the cut (unchanged) | N/A |
| Hold | 47-char line | stays 5.0 s, then fades over 0.6 s | N/A |
| Debug list | `--comms=a,b,c` (debug build) | requests a, b, c in order once the level starts (combat ones queue) | empty items skipped; no ids → existing warning |

**Operator test data (added 2026-10-09 at the user's request):** `dev_comms_check` gains a second Tarek line straight after the first, so it covers a same-speaker click and speaker-change handovers. New `dev_combat_isolde_2` (Isolde, one line, ≤ 50 chars) goes in `dev.json`. `--comms=` accepts a comma-separated list, so `dev_combat_check,dev_combat_isolde_2,dev_combat_vale` plays key-in, then click, then handover. The mic-click cue is diegetic: it's the speaker keying their push-to-talk, not the player's input.
